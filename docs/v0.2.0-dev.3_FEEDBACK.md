## 一、dev.3 反馈（原始 4 条）

### 1. 教程一塌糊涂。很多事件节点发生的完全不对，应该返航到港后触发的剧情在启航时就触发了。

**状态：已修复（2026-10-26）。**

根因（不是内容文案问题，是事件时机与阶段耦合）：

- `ui:arrival_settled` 在结算页**每次挂载/重建**时都会观察一次（含结算页自己
  `call_deferred("_refresh")`），一次抵达至少重复上报 2 次；`ui:chart_opened` 同理，
  海图页每次重建都会重报。剧情阶段因此可能在玩家没做动作时被推进。
- `DEPARTURE_VEIL`（离港云层 0.7 s）既不属于 3D 离港演出也不属于海图演出，而
  `voyage.start` 后领域状态已 `at_sea=false`，重建会掉回上一页（出航时恒为海图）
  并再次上报 `ui:chart_opened`。
- 内容层 `depart_brief` / `second_depart` 是「出航指示」阶段却直接等
  `ui:arrival_settled`，出航与抵达两步耦合；`_settlement_summary` 离港时未清空。

修复：`ui:arrival_settled` 只在 `_finish_presentation()` / `_full_stop_after_voyage()`
各发一次；`ui:chart_opened` 移到真实打开动作 `_on_nav("sea_chart")`；`DEPARTURE_VEIL`
归入 3D 演出分支；离港清结算摘要；内容拆出 `first_arrival` / `second_arrival` 两个
「等抵达」阶段，出航阶段改由 `cmd:voyage.start` 收起。修复后实测时间线：`voyage.start`
⇒ `first_arrival`（无卡、无抵达剧情）→ 抵达结算 ⇒ 恰好 1 次 `arrival_settled` ⇒
`second_port`；整窗 `story.observe` 恰好 2 次；结算页重建 ×3 与离港云层重建均 +0；
海图开/关各 +1、重建 +0。契约与阶段表见 [STORY_TUTORIAL.md](design/STORY_TUTORIAL.md) §3/§6。

### 2. 海图标注的航线距离和实际算物资事件消耗的距离完全不一致，怀疑是接的1.0的地图跑的2.0的动画

**状态：已彻底修复（2026-10-26，海图唯一真相）。** 玩家的怀疑在实质上是正确的：此前
游戏同时跑「抽象对局地图」与「坐标海图世界」两套数据，航行耗时/煤水扣费走抽象地图的
随机里程（90–220），海图动画走坐标世界，两者从未同源。上一轮只把「读数」接到抽象地图；
本轮按「直接不要拓扑，一切均以海图为唯一真相」**取消第二套世界**：

- `state.data["world_map"]`（`WorldMap`）是唯一世界与唯一拓扑；`WorldGenerator.generate_chart`
  一次生成 5 陆地布局 + 可玩连通图（MST + 按几何成本补边到 `world_profiles.edge_density`
  预算，起点度 ≥2、无重边、全连通）+ 每条边的绘制路径。`distance` = **路径折线长度**
  （两位小数），`base_risk` 按 `route_templates.risk_range` 用命名流按 pair 掷出；港口
  archetype 在拓扑后按 BFS 分配，必需设施在 `required_facility_max_edges` 内。
- `GameState.world()` 的 ports / routes 由 `ChartWorldProjection.from_chart` 从同一张海图
  派生（MapOps / 委托 / 航行 / BFS / 探索全部读它）；`sea_chart.view` 只有 `distance` 一个
  距离字段、风险读同一条边，`voyage.preview` 读同一份 `routes`——海图弧长、标注里程、实际
  扣煤/耗时、风险全部同源。上一轮的 `chart_distance` / `distance_source` / `sailable=false`
  双口径字段与不可出航分支已删除。
- 旧抽象拓扑生成器 `MapGenerator` 退出战役链路（文件保留、无调用）；`route_templates.
  distance_range` 与旧随机里程不再影响世界。教程 `tutorial_express` 时限改为与距离严格成
  比例（`max(0.5, distance / 13.5)`），保住「标准迟到 / 极速准时」：实测 seed 20260421
  首航 25.14 海里、deadline 1.86h、标准到达 2.06h（迟到）、极速到达 1.61h（准时）。
- 实测（seed 4242）：5 港 6 边；`port_0→port_1` 146.43 海里（281 点绕岛）、
  `port_0→port_4` 26.59（21 点）、`port_1→port_2` 67.46；三条边的
  `WorldMap.edges[].distance`、`GameState.world().routes[].distance`、
  `sea_chart.view.distance` 与 `voyage.preview.distance` 逐项相等（浮点一致），
  `base_risk` 也来自同一条边。逐项一致性与同 seed 确定性由 `test_world_unity` 锁定。
- 契约见 [NAUTICAL_CHART_SYSTEM.md](design/NAUTICAL_CHART_SYSTEM.md) §4.1.1 与
  [WORLD_SCHEMA_V2_RUNTIME.md](design/WORLD_SCHEMA_V2_RUNTIME.md) §6.3.1。

### 3. 教程缺少强制引导（全屏只有唯一部分可以交互，其余地方用半透明遮罩盖住）【该功能需要使用框架提供的接口而非写死】

**状态：已实现（2026-10-26，框架级接口）。**

新增 `SNFocusOverlay`：四块半透明遮罩拼出目标矩形（目标区域照常收点击，其余区域
由 `MOUSE_FILTER_STOP` 吞掉）、黄铜边框与提示文案，纯 `SNSkin` 纹理/token，resize 重排、
目标不在屏上时 fail-open。内容只在 story 阶段声明语义目标：
`focus: {target: "market_supply" | "chart_entry" | ... , text_key}`；`story.view.focus`
透传，Shell 负责把语义 target 解析成真实控件矩形。Schema
（`common.schema.json#/$defs/story_stage.focus`）与 SNModMaker 嵌入式 bundle 已同步。
已覆盖 `supply_brief` / `supply_finish`（市场补给区）、`supply_hold` / `chart_brief`
（海图入口）；剧情卡打开时卡优先，推进 / 跳过自动清除。

### 4. 各种交互提示需要一个 tooltip 从交互处浮出。目前是在页面上方的提示框，可是玩家是在下面交互的，必须拉回顶部才能看到交互提示。

## 二、本轮实机测试反馈（2026-10-26，5 条）

### 1. 市场购买物品时，需要将其 icon 浮于鼠标指针上，象征「拿起」，数字跟随鼠标指针走，鼠标移过去再点击就可放下。

**状态：已实现（2026-10-26）。**

新增 `SNCarryGhost`：市场商品左键点出待交易量后，icon + 名称 + `×N` 跟随鼠标
（原生拖拽时自动让位），船舱 / 仓库落点进入「已武装」高亮；移动到落点单击即
`trade.buy {amount = 待交易量}`（点落点内的子格子也有效），右键取消。委托货 /
仅收购品种仍锁定；原生拖拽保留为兼容手势。卖出方向仍走拖拽（本轮范围）。
契约见 [MARKET_UI_REFACTOR.md](design/MARKET_UI_REFACTOR.md) §2。

### 2. 委托不再显示目的地港未发现的委托。

**状态：已修复（2026-10-26）。**

`port.view` 的普通委托列表只输出**目的港已发现**的实例（`state.contracts().offers`
池仍保留 3 条，目的地被发现后同一条自动重新出现，不改经济/确定性/存档）；
主线 offer 作为引导在生成时自动揭示目的港（`MapOps.discover` + `WorldOps.discover_port_id`），
因此主线永远不会因迷雾被隐藏。

### 3. 主线委托不再有时间限制。主线委托定位应该是引导。（从当前第三委托开始）

**状态：已实现（2026-10-26）。**

「第三委托」= `main_03` 起（`main_03/04/05`；`main_01/02` 保留教程的限时设计）。
新增 `FormulaRegistry.none → 0` 作为「无期限」哨兵，`create_instance` 对 ≤0 存
`deadline = 0.0`；`ContractOps.complete` 对无期限委托恒视为准时、不发 `contract.late`、
不计入准时率，完成奖励（原 `on_time_bonus`）作为「完成 +N」无条件发放（经济数值不变）。
视图 / 委托卡 / 总览 / 出航确认全部显示「引导委托 / 无期限」。旧存档用
`ContractOps.is_untimed()`（`deadline<=0` 或 `kind=main 且 sequence>=3`）覆盖，不写迁移。

### 4. dev.3 的 feedback 好像也没有修改。

**状态：已处理。** 见本文件第一节 1–4 条的修复说明；本轮同时修掉了 dev.3 反馈的

### 5. 当前 terminal 场景没有船。

**状态：已修复（2026-10-26）。**

根因：`PortStage._rebuild_ship()` 在 landmark 门面模式（`grand_harbour_terminal`，
即起始港铁港）里无条件提前 return，玩家船从未创建；市场 / 补给 / 船厂站位同样受影响。
修复：门面模式正常挂玩家船（专用门面泊位 z=6、按船体缩放到 0.75；market / supply 用
站位中心 −13.5 避免被 620 px 泊位面板挡住）；新增 2 艘划艇 + 1 艘货驳作为氛围船并
自动合批；ShipSteam 重锚到船顶；门面模式改由 landmark **成功实例化**决定，GLB 缺失时
回退完整港区（仍出船）。实测门面四站位 96 draws / 83.5k tris（draws ≤120；tris 超出
60k 预算来自 terminal 自身 59,450 tri + 船体装配 13,372，属既有构成）。截图见
`docs/design/screenshots/port_stage/` 与 `docs/design/screenshots/skin/`。

## 三、本轮遗留 / 已知边界

- 海图已是唯一世界（拓扑 / 几何 / 距离 / 风险同源），上一轮「两套世界几何未统一」条目
  关闭。剩余边界：里程由绘制路径几何决定（约 25–150 海里，含绕岛），`route_templates.
  distance_range` 不再影响世界；路径坐标按两位小数存盘，重算折线长度与存值差 < 0.05 海里。
- 固定 5 陆地 × 每陆 1 港的布局让**拓扑**在不同 seed 间基本稳定（海岸抖动 / archetype /
  边风险不同）；若后续需要每 seed 不同的连通关系，可在补边时从最便宜的若干候选里随机抽取。
- 航行演出仍压缩到 2–9 s：抵达结算在按启航后约 4–6 s 出现，属于演出节奏的观感问题
  （本轮只修了「时机/事件」缺陷，未改演出时长）。
- 教程 focus 遮罩未纳入自动截图覆盖（用组件 rect / 遮罩断言验收）。
- 60 m 级 freight/ironclad 在门面 0.75 缩放下水平投影会略出左缘，后续可按船体长度自适应。
- `measure_port_stage.gd` 的样本数改为动态 `2 + station_ids().size()`（4 站位 = 6 样本）。
