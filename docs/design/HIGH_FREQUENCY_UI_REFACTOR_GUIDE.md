# 高频决策页面重构指南

> 适用范围：市场、委托、补给与船厂。目标不是按数据字段排列信息，而是让玩家在 3 秒内理解状态并做出决策。

## 1. 共用页面规范

所有高频决策页统一采用以下骨架：

```text
页面标题 + 当前港口
关键资源摘要
────────────────────
筛选 / 分类 / 状态切换
主要决策区域
────────────────────
固定操作区或明确主按钮
```

基础规格：

- 内容最大宽度 1280px，页面边距 32px，卡片间距 16–20px。
- 正文不低于 14px，关键数字使用 18–24px。
- 主要操作统一使用 `SNPrimaryButton`。
- 禁用按钮旁必须显示原因，不能只降低透明度。
- 页面数据刷新不播放全屏转场；只让变化的数字、行或卡片播放 120–220ms 反馈。
- 业务组件只发出 `command_requested` 信号，不直接访问 CommandBus。

建议将页面从 `framework/ui/shell/main.gd` 拆分为：

```text
framework/ui/screens/
  market_screen.tscn
  contracts_screen.tscn
  supply_screen.tscn
  shipyard_screen.tscn
```

统一接口：

```gdscript
func bind(view_model: Dictionary) -> void
signal command_requested(command: StringName, params: Dictionary)
```

Shell 继续负责查询、命令和导航，页面只负责展示与产生用户意图。

## 2. 市场页

### 2.1 决策目标

玩家需要快速回答：

1. 什么值得买？
2. 什么值得卖？
3. 买多少会超重或花光钱？
4. 当前售价相对持仓成本是否盈利？

### 2.2 推荐布局

```text
市场行情                         金币 2,480｜载重 18/32
[全部] [工业品] [消费品] [补给]        [仅看持有]

商品        趋势/港存     买入价    持有/均价       操作
钢材图标    ╱╲╱╱ +12%     84       3件 @69       [-] 1 [+] [买入]
香料图标    ╲╲╱╲  -8%    142       0件            [-] 1 [+] [买入]
红茶图标    ─╱─╲  +1%     63       5件 @51        [卖出] [买入]
```

### 2.3 `SNMarketRow` 固定结构

- 商品区：40×40 图标、名称、分类。
- 趋势区：迷你折线、百分比、港口库存。
- 价格区：当前买入价、卖出价。
- 持仓区：数量、平均成本。
- 预估区：
  - 买入时显示总价与买后载重。
  - 卖出时显示预计利润，例如 `+65`。
- 操作区：`− / 数量 / +`、买入、卖出。

买卖按钮需要形成明确分组：

- 买入组使用黄铜色。
- 卖出组使用深青描边。
- 只有收购能力时隐藏买入组，并显示“本港不出售”。
- 没有持仓时禁用卖出按钮，并显示“船上无货”。

### 2.4 ViewModel 补充

当前 `PortViewQuery` 已提供价格、库存、持有量、可售、`buyable`、持仓均价和趋势。真实折线还需要价格历史：

```gdscript
{
    "trend": "up",
    "trend_percent": 0.12,
    "recent_prices": [72, 75, 73, 79, 78, 84]
}
```

不要根据单个 `up/down` 状态伪造折线。历史不足时显示箭头和“样本不足”。

### 2.5 验收标准

- 三秒内能找出最高涨幅商品。
- 玩家无需心算即可判断卖出是否盈利。
- 调整数量时，总价、载重和港存即时变化。
- 交易成功只更新对应行、金币和载重，不整页闪烁。
- 960px 宽度下可以隐藏分类文字和次要库存列，但必须保留价格、持仓与操作。

## 3. 委托页

### 3.1 决策目标

玩家需要快速比较目的地、剩余期限、载重、风险与收益。

### 3.2 `SNContractCard` 固定结构

```text
[主线] [中等风险]

失踪的蓝图
工业联合会

目的地       剩余期限
自由镇       2天18时

载重         预计航程
4格          1天16时

运送密封机械箱……
最多显示两行，多余省略

报酬 860 金币       +12 声望
              [规划航线] [接取委托]
```

卡片固定分为五个区域：

1. 状态区：主线/普通、风险、已接取。
2. 标题区：名称、委托方。
3. 四宫格数据区：目的地、剩余期限、载重、预计航程。
4. 说明区：最多两行。
5. 报酬与操作区：金币、声望、按钮。

### 3.3 页面分组

```text
[可接委托 3] [进行中 1] [已完成]

主线委托
────────
普通委托
────────
```

- 桌面端采用两列，960px 以下改为单列。
- 主线卡可以跨两列，但不能只依赖金色边框，必须保留“主线”文字标签。
- 卡片高度和指标位置保持一致，便于横向比较。

### 3.4 ViewModel 补充

```gdscript
{
    "destination_name": "自由镇",
    "remaining_hours": 66.0,
    "remaining_label": "2天18时",
    "cargo_slots": 4,
    "estimated_hours": 40.0,
    "risk_tone": "warning",
    "risk_label": "中等",
    "reward_money": 860,
    "reward_reputation": 12,
    "can_accept": true,
    "blockers": []
}
```

风险等级和预计航程应由查询层生成，卡片不能自行调用航行公式。

### 3.5 验收标准

- 任意两张卡可以按同一纵向位置比较期限和报酬。
- 优先显示剩余期限；必要时同时提供绝对时间 Tooltip。
- 载重不足、持有上限或航线未知时，按钮禁用并显示具体原因。
- 接取成功后原位置先播放盖章反馈，再移动到“进行中”。
- 剩余不足 24 小时的委托进入危险色，并保留“即将到期”文字。

## 4. 补给页

现有 `SupplyViewQuery` 已提供价格、港存、可买上限和维修报价，适合作为第一个落地页面。

### 4.1 推荐布局

```text
补给与维护                     金币 2,480

┌ 煤炭 ──────────┐  ┌ 淡水 ──────────┐
│ 31 / 50         │  │ 39 / 50         │
│ ██████░░░░      │  │ ████████░░      │
│ 安全线 20       │  │ 安全线 15       │
│ 预计续航 6.2天  │  │ 预计续航 9.8天  │
│ 18金币/单位     │  │ 7金币/单位      │
│ [+1] [+5] [补满]│  │ [+1] [+5] [补满]│
└─────────────────┘  └─────────────────┘

船体维护                   载重状态
耐久 82 / 100              商品 13｜委托 5｜可用 14
维修至满：360金币          煤水使用独立储罐
[维修至满]
```

煤炭和淡水直接使用 `SNResourceMeter`，外层封装 `SNSupplyCard`：

- 图标和资源名称。
- `SNResourceMeter`。
- 单价和港口库存。
- `+1 / +5 / 补满`。
- 即时总价。
- 购买限制说明。

### 4.2 ViewModel 补充

```gdscript
{
    "coal": {
        "current": 31.0,
        "maximum": 50.0,
        "safe_level": 20.0,
        "estimated_days": 6.2,
        "price": 18,
        "port_stock": 74,
        "max_buy": 19,
        "fill_cost": 342,
        "blockers": []
    }
}
```

`estimated_days`、`fill_cost` 和 `max_buy` 必须由查询层返回，避免 UI 复制消耗率、载重与价格规则。

### 4.3 验收标准

- 存量、最大值、安全线和预计续航同时可见。
- 点击补满前即可看到总价。
- 补满受金币、容量或港存限制时，按钮显示“购买最大 N”。
- 买入成功后只更新对应资源卡、金币和提示。
- “煤水不占货舱”在页面永久可见，而不是只放在 Tooltip。

## 5. 船厂页

船厂是四页中最复杂的页面。先建立“槽位—当前模块—候选替换”的交互模型，再设计模块卡片。

### 5.1 推荐布局

```text
┌──────── 船体与槽位 ────────┐ ┌──── 当前模块 ────┐ ┌──── 候选模块 ─────┐
│                            │ │ 标准锅炉          │ │ 双胀式锅炉         │
│       船体侧视示意          │ │ 航速 10.2         │ │ 价格 1,460         │
│                            │ │ 煤耗 5.0/日       │ │                    │
│ [锅炉] [货舱] [导航] [安全] │ │ 事故率 8%         │ │ 航速 +2.4          │
│                            │ │ 重量 10           │ │ 煤耗 +1.2          │
└────────────────────────────┘ └───────────────────┘ │ 事故率 −2%         │
                                                    │ 重量 +4            │
                                                    │ [购买并安装]       │
                                                    └────────────────────┘
```

固定交互顺序：

```text
选择槽位 → 查看当前模块 → 选择候选 → 查看差异 → 安装
```

### 5.2 建议组件

`SNShipSlot`：

- 类型图标。
- 当前模块名称。
- 空槽、已安装、锁定和选中状态。

`SNModuleCard`：

- 名称、等级、价格和重量。
- 是否已安装。
- 安装阻塞原因。

`SNStatDelta`：

- 当前值、新值和差值。
- 单位与好坏方向。
- 不根据数值正负自行判断颜色。

例如煤耗增加是坏事，而风险数值降低是好事：

```gdscript
{
    "stat_key": "coal_rate",
    "label": "煤耗 / 日",
    "current": 5.0,
    "candidate": 6.2,
    "delta": 1.2,
    "unit": "",
    "is_better": false
}
```

### 5.3 ViewModel 补充

当前 `ShipyardViewQuery` 已提供 `effect`、`blockers` 和 `can_install`，建议增加标准化比较结果：

```gdscript
{
    "slot": "boiler",
    "installed": {...},
    "candidates": [{
        "id": "...",
        "comparison": [...],
        "can_install": false,
        "blockers": [{
            "code": "insufficient_money",
            "label": "还差 420 金币"
        }]
    }]
}
```

### 5.4 验收标准

- 点击槽位后只展示对应模块，不把全部类型堆在同一列表。
- 每个候选最多显示四项关键差异。
- 安装前能明确看到重量、速度、煤水消耗和风险变化。
- 禁用按钮显示完整阻塞原因。
- 已安装模块与可购买模块具有不同状态。
- 960px 以下改为“槽位在上、当前/候选在下”，不横向压缩三栏。

## 6. 建议新增组件

按复用价值排序：

1. `SNStatDelta`
2. `SNQuantityStepper`
3. `SNSparkline`
4. `SNActionFooter`
5. `SNMarketRow`
6. `SNContractCard`
7. `SNSupplyCard`
8. `SNShipSlot`
9. `SNModuleCard`
10. `SNEmptyState`

前四项是基础积木，后六项是业务组件。

## 7. 推荐实施顺序

1. **补给页**：数据最完整，用于验证新组件、局部刷新和禁用原因。
2. **委托页**：建立固定卡片结构和响应式两列布局。
3. **市场页**：增加价格历史后实现折线、数量选择和即时成本。
4. **船厂页**：最后实现槽位选择和标准化差异模型。

每完成一个页面，都应在 `framework/ui/showcase/ui_kit_showcase.tscn` 中加入其核心组件的正常、hover、禁用、错误和空数据状态。游戏页面不应成为唯一的视觉测试入口。
