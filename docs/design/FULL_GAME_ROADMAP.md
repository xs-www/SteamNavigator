# 正式版路线图：从 MVP 到持久模拟经营

> 状态：方向草案（2026-10-19）  
> 架构依据：[持久模拟经营战役](PERSISTENT_CAMPAIGN_ARCHITECTURE.md)  
> 目标：每个阶段都交付一个可玩的纵向切片，而不是先铺完所有数据再整合。

## 0. 首个完整纵向切片（目标形态）

**1 个区域、3 个港口、1 处遗迹、1 个基地点、2 艘船、3 类敌人、1 条自动贸易航线。**

玩家可以：随机开局 → 探索区域 → 组建舰队 → 打一场战斗 → 建一个基地 → 设一条自动贸易线 → 进一次遗迹 → 存档后继续。  
这一圈跑通，才允许扩内容量。

## 阶段 0：正式版地基

- [ ] 冻结 MVP 1.0 行为与存档；宣布 Content Schema 1.x 只读。
- [x] `content_types.json` 单一真源（框架 / Schema / 编辑器 / SDK / 文档）。
- [x] 存档 Schema 2.0；1.x 旧档迁移器 + 回归测试。
- [x] Content Schema 2.0 草案骨架：`schemas/v2/common` + start/world/region/site/route（planned，暂不加载）。
- [ ] Content Schema 2.0 系统类型：weather / faction / discovery → fleet / combat / base / trade / ruins。
- [ ] `CampaignState` 分区与多战役存档槽；新战役 / 继续 / 自动存档 UI。
- [ ] 模拟时钟、暂停/加速、tick 调度与区域分层模拟框架。
- [ ] 明确首个纵向切片的内容清单与验收脚本。

验收：旧 MVP 存档可迁移打开；新战役可创建、保存、读回；同种子 + 同命令序列结果一致。

## 阶段 1：广域海图与探索

- 区域 / 地点 / 航线 / 迷雾 / 发现度；港口作为区域内的特殊地点。
- 旅行从“港口到港口”升级为坐标 + 航线 + 时间消耗；保留 MVP 航线作为已测绘航道。
- 编辑器增加世界区域、地点、世界配置视图与可解性检查。

验收：大区域内可自由探索、发现遗迹/基地点；远处区域低细节模拟；玩家能靠探索获得稳定收益。

## 阶段 2：舰队与战斗

- 多船舰队、船长/船员、编组与跨区调度；单船逻辑泛化为舰队逻辑。
- 模块分类收敛为 `boiler / cargo / utility / cabin / crew`；导航与安全并入 `utility`，不再单独设内容类型或编辑器分组。
- 战斗先做自动结算 + 少量选择，再评估战术格；数据侧先做武器、敌人原型、遭遇表、掉落表。
- 战斗契约与外部草案的采纳边界见 [战斗系统架构评审](COMBAT_ARCHITECTURE_REVIEW.md)：本阶段只做自动结算，实时战术与部位伤害后置。
- 战斗消耗与舰队状态、补给、耐久、船员挂钩。

验收：2v2 战斗可自动/半自动结算，战利品进入经济；舰队可跨区移动；失败产生可恢复损失。

## 阶段 3：基地建设

- 基地点、建筑、升级、生产配方、仓储与工人；建筑产出接入舰队/战斗/贸易。
- 基地有维护费、防御与事件；失守进入流亡而非删档。

验收：基地可生产至少一种舰队/战斗必需部件；生产链在存档中持续运行。

## 阶段 4：自动化贸易

- 贸易航线、自动买卖规则、风险与收益；跑在 tick 模拟上，与区域价格和 NPC 互动。
- 玩家可暂停/覆盖自动决策；失败、海盗、天气进入事件系统。

验收：一条自动航线在玩家探索时持续产生收益与风险；数值不破坏手动贸易。

## 阶段 5：遗迹探索

- 程序化遗迹、房间/事件链、危险与战利品；复用事件/条件/效果 DSL 和战斗。
- 远征队伍来自舰队/船员；带回遗物、蓝图或剧情线索。

验收：一次完整远征可重复生成但同种子确定；收益与风险可平衡。

## 阶段 6：整合、内容量与发布

- 完整纵向切片贯穿：开局 → 探索 → 舰队 → 战斗 → 基地 → 自动贸易 → 遗迹 → 长线目标。
- 教学、目标线、失败恢复、存档管理、设置与本地化。
- Mod API 2.0 / Content Schema 2.0 冻结；官方内容包版本化；旧档迁移矩阵。
- 平衡抽样（多难度/多种子）、性能预算（大世界 + 多舰队）、编辑器 round-trip 与 CI 门禁。

验收：新玩家 30 分钟内理解核心循环；10 小时存档可继续；删除/新增可选模组有明确行为；发布包验收通过。

## 并行策略

- 世界/探索是地基，优先。
- 舰队与战斗互为依赖，作为一个工作流推进。
- 基地可在世界稳定后并行；自动贸易依赖基地与舰队；遗迹依赖世界与战斗。
- 每个阶段结束必须能在一个战役存档里连续玩，不做“只完成系统、不接入主循环”的交付。

## 不做什么

- 不在阶段 0 同时开工所有系统。
- 不用任意脚本模组实现新机制；新机制先进入框架与 Mod API。
- 不为“内容多”牺牲存档兼容与确定性。
