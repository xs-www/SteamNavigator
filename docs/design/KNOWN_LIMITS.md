# 已知边界与暂缓项（Known Limits）

> 从 README 拆出的实现边界清单；判断某个需求是否已实现前先读这里，避免把“当前限制”当成 bug。

- 材料随船运输仍计入货舱容量；GDD 9.1 中“材料不占货舱容量”本轮只对未安装模块（transit）实现。
- 船厂仓库/运输 UI 为基础版：材料按固定 5 件批量存取，尚无数量步进或批量选择。
- 通关总结页为数据化总结，不含航线回放、成就与统计对比。
- 船厂改装态纵剖图是一张 2D 授权贴图；正常态已是真实 3D 船体舞台（固定机位、只做表现，不含环绕与场景热点），3D 船体资产缺失时回退程序化 2D 占位。贴图与当前可玩船型视觉也不完全一致（纵剖图 / 船卡为铁甲舰风格）。**主界面已是全窗 `PortStage` + 紧凑 HUD（含资源图标）+ 主题化两侧招牌 + 底部状态条 + 详细总览抽屉；港口街景 normal 47 件与 `port.diorama` 已接线，设施/街景/玩家船静态合批后实测 63/56 draw calls；剩余 2.5D 工作是港务/市场等独立舞台、出航/进港演出、质量档位/低配回退与 L2 LOD。**
- **运行时船体装配的边界**：帆索只对实测 1:1 吻合的船体做套件替换（PF 桅/桁、SF 桅），其余保留 GLB 内烘焙帆索，避免双层；kit 帆面尺寸与烘焙件不符，整桅帆重挂留待后续批次。Phase 1 已把船厂武器购买/仓库/装配接到持久 `ship.weapon_loadout`，战斗与视觉装配消费同一状态，空 socket 不再获赠默认武器。当前仍不含武器打造、弹药经济、炮门武器装配与单件武器耐久；港口舞台合批后武器瞄准 / 后坐句柄仍会失效（战斗层接入时需要不合批旁路）。详见 [SHIP_VISUAL_ASSEMBLY.md](SHIP_VISUAL_ASSEMBLY.md) §9。
- **内容资产全部走模组**：船体/模块/道具模型与港口横幅随 `core` 模组发布（`dev_mods/core/assets/**` + manifest `model.*`/`banner.*` 键），发布包 PCK 已排除 `assets/models/*`；运行时由 `ContentAssetLoader` 读取模组内原始 `.glb`/`.png`。本体内只保留框架资源（代码、Theme/字体、UI 外壳图、音频、水面 shader/材质/贴图）。新增内容模型请放 `dev_mods/core/assets/models/<category>/` 后重新 `pack_core`，不要放回 `res://assets/models`。
- UI 是最小可用外壳，设施名称部分为中文硬编码；海图可按已访问港口打开上次在港的市场快照。
- 全屏航海图页已接入 Shell（M 键 / 导航「海图」/ 状态条「海图 ▶」/ 港口招牌；出航确认在页内弹窗）。**2026-10-26 起海图就是唯一世界（拓扑 / 几何 / 距离 / 风险同源）**：`state.data["world_map"]`（`WorldMap` 1.2）是唯一世界与唯一拓扑，`GameState.world()` 的 ports/routes 由 `ChartWorldProjection.from_chart` 派生；开局 `WorldGenerator.generate_chart` 一次生成 5 陆地布局 + **完全图拓扑**（任意两港一条边，5 港 10 条；MST / 补边 / `edge_density` 已退役）+ 每条边的绘制路径 / 折线长度 `distance` / `base_risk`，港口 archetype 在拓扑后分配并保证必需设施在 N 边内。海图弧长 = 标注里程 = `voyage.preview` 计费里程 = `world.routes[].distance`；`sea_chart.view` 只有 `distance` 一个距离字段，旧 `chart_distance` / `distance_source` / 不可出航边已删除。**可出航 ≠ 可通航**（2026-10-26）：物理完全图只说明航线存在，玩家还必须用**委托自带海图 / 剧情效果 / 酒馆 `chart.buy`** 解锁（`campaign_world.unlocked_route_keys`，发现港口不解锁）；未解锁航线的 `voyage.preview` / `voyage.start` / `clue.travel` 返回 `route_locked`，`explore.start` 不受限；海图面板对未测绘航线禁用启航并提示在酒馆购买海图。已知边界：里程由几何决定（约 25–150 海里，含绕岛），`route_templates.distance_range` 与旧抽象生成器的随机里程不再影响世界；路径坐标 / distance 按两位小数存盘，重算折线长度与存值差 < 0.05 海里（测试容差）；旧抽象拓扑生成器 `MapGenerator` 已退出战役链路（文件保留、无调用）。开发期不做旧存档 / 旧拓扑适配：无 `world_map` 的旧档海图显示无数据提示，按需重开新局；旧档没有 `unlocked_route_keys` 时视为「一条航线都没测绘」。完整规则见 [ROUTE_UNLOCK_SYSTEM.md](ROUTE_UNLOCK_SYSTEM.md)。
- 存档已支持 save schema 1.x → 2.0 迁移（回填 campaign 元数据与分区，state/content schema 分离）；模块实例表 `ship.module_instances` 与 campaign 分区均由惰性 ensure 补齐；声明式 ID 别名迁移仍未实现，新字段继续通过惰性 ensure 补齐。
- 模块 condition 已实际影响锅炉输出、导航/安全修正、货舱/客舱容量与 modifiers；仍未实现战斗按部件定向命中、单槽维修或备件库存。
- **Content Schema 2.0 Phase B/C/D0–D5/E 已落地（Finalized）**：42 个 active 类型与 3 类草案全部为 2.0（0 个 1.0 runtime；D1 新增 6 个战斗类型、D2 新增 4 个舰队类型、D3 新增 5 个基地类型、D4 新增 2 个自动贸易类型、D5 新增 5 个遗迹类型）；Phase E 冻结 1.0 内容生成/读取（`FrameworkInfo.CONTENT_SCHEMA = 2.0`，编辑器 fallback 2.0，1.0 内容报需要 2.0 的错误），发布门禁 `tools/check_content_schema_v2.mjs` 强制全 2.0；`CampaignFactory` 从 `start_profiles` / `world_profiles` / `map_configs` / `starting_scenarios` 装配战役并写入 `campaign.setup/content_versions`；`map_profiles` 已退役，`map_configs` 是唯一场景配置；D0 的 `data.sim`、D1 的 `data.combat` 与 D2 的 `data.fleet` 惰性持久化；编辑器草案为 `story_arcs` / `story_levels` / `combat_ai_profiles` 3 类（schema bundle 48 个）。**「运行时不加载」不是静默忽略**：未注册类型 / 版本不符仍按 mod error 拒绝，Core 必需包会让启动进入 `Degraded`。
- **剧情模式数据契约 V2 冻结中（2026-10-27）**：V1 已被取代。V2 目标为完全数据驱动——手写陆地+航道、2D 叙事（文本/说话人/立绘/背景/音频/选项）、关卡内嵌 `tasks[]` 复用 quest 状态机、页面/动作 available/locked(reason)/hidden 三态与阶段覆盖；契约见 [STORY_MODE_DATA_CONTRACT_V2.md](../specs/STORY_MODE_DATA_CONTRACT_V2.md)。**运行时仍未加载**：`story_arcs` / `story_levels` 还是草案类型，加载链（S2）、运行时、UI、编辑器剧情页都尚未实现；Schema/校验/冻结门禁待 V2 落地后更新。
- 无头退出时 Godot 会报告静态注册表/脚本的 ObjectDB 泄漏警告；测试退出码仍为 0，不影响运行。
- **游玩数据上传（Telemetry，2026-10-27）**：设置页「允许上传数据」默认关闭；只有正常退出（`_graceful_quit()`）才会落盘并尝试上传本局会话，崩溃 / 强制结束进程内未落盘的缓冲会丢失，已落盘的 pending 在下次启动补传；退出流程最多等 3 秒上传，慢网络下更多会话留到下个启动周期。官网接收端为单实例内存限流（120 次/小时/IP），不做跨实例统计、去重报表或管理页面；本地预览（`website/tools/serve.mjs`）与生产（`website/server/telemetry.mjs` + nginx 反代）使用同一 handler。契约见 [TELEMETRY.md](TELEMETRY.md)。
